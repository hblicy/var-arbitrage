# 资金费套利策略监控实施计划

> 使用 writing-plans、executing-plans、test-driven-development 在当前任务顺序执行。未经用户批准不启动开发子代理；完成后可按审查技能启动只读审查。

**Goal:** 为已有资金费套利平台增加完整持有期收益、历史质量、持续信号与分档容量，保留原价差复核及持仓功能。

**Architecture:** 新增纯计算模块、独立 SQLite 历史/事件存储及监控协调模块，沿用现有采集器与 MarketDatum。API 和 CLI 复用同一监控流程；页面增加资金费视图，保留原始机会视图。历史库只新增自己的表，不修改持仓/用户表。无交易写入、无新依赖。

**Tech Stack:** Python、SQLite、FastAPI、React、unittest、node:test。

## 已确认设计和实施默认值

- 在已批准的建议范围内实施。默认持有期 8h（用户可调整），评估 1/4/8/24h。
- 同基础数量对冲，金额为单腿最大名义金额；净收益分母不是保证金。以当前盘口作为退出成本情景，费率保持当前值；不承诺价差回归。明确区分交易所提供的结算时间和按周期推算的时间。
- 历史按有效采样时间加权，按分钟聚合。覆盖率以完整回看窗口为分母，不填补断线；记录价格差和小时资金费差的均值、波动、正费差占比。保留 48h 数据，默认回看 4h、有效覆盖率 80%。
- 连续达标默认 120 秒，净收益门槛默认 20 bps；每次都要求足够历史、有效行情、实际盘口支持计划金额。数据缺失重置累计；恢复后重新观察。事件记录状态变化，重启后重新计时，避免把停机时间算入。
- 金额档位 1,000/5,000/10,000 USD；共同数量匹配双边盘口，计算四方向 VWAP。容量为当前可见盘口内满足净收益门槛的估计最大金额，含 book-limited 标记，不冒充账户可用余额。
- 深度采集只对正向资金费且基础估算达标的候选执行，每轮最多 20 个方向；按市场去重、有限并发，未检查方向明确标记，不推送。无深度接口的路线保留人工观察。
- 页面展示收益拆解、结算次数、历史曲线/覆盖率、状态/持续时间和容量，支持切换持有期和查看事件。通知使用默认持有期与已持续达标的深度结果，保留已有冷却和持仓退出通知。
- 先复用现有 REST 和周期元数据缓存；本轮不盲目改成全所 1s 请求。源时间/延迟/缺失参与信号判定。
